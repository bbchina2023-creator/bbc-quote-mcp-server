### DEV-016.48 / DEV-016.49 release-gate hardening

`4.1.48` added a source-only pre-calculation gate and normalized package status semantics:

- calculation-blocking intake issues stop write calculation before a new calculation snapshot/derived output is created;
- final-quote-only blockers permit calculation but keep package status `NEEDS_MANAGER_INPUT_BEFORE_FINAL_QUOTE`;
- a verified calculation alone no longer makes a blocked package appear quote-ready;
- package status is derived consistently from intake/rate gates and verified calculation state.

A follow-up audit found that the manual `generateQuoteDocuments()` path executed `validateFinalQuoteIntake_(intake)`, while the Chat API `bbcChatApiGenerateQuote_()` path still built quote output without calling that final intake gate. That was a release-critical inconsistency.

`4.1.49` closes it:

1. `bbcChatApiGenerateQuote_()` now executes `VALIDATE_FINAL_QUOTE_INTAKE` immediately after final source reconciliation and before building client context or copying/writing the quote template.
2. Manual and API quote-generation paths now use the same final-quote blocking invariant.
3. A verified snapshot cannot bypass unresolved manager, owner-decision or other final-quote blockers.
4. Regression explicitly verifies the final gate exists in both generation entry points.
