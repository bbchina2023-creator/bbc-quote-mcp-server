# DEV-016.40 Staging Release Contract

Status: RC1 calculation/document layer verified. Primary manager workflow is direct ChatGPT intake from the current deal documents. MCP staging remains an optional integration contour and is not a release blocker for the manager workflow.

## Primary manager workflow — frozen

For every new deal:

1. The manager provides the input documents for that deal in the current ChatGPT conversation.
2. ChatGPT reads and reconciles only those current-deal documents as the source of deal-specific values.
3. If a downstream deterministic operation requires Drive IDs/URLs, ChatGPT itself stores/resolves the files in Google Drive and passes the required references. This is an internal technical bridge, not a manager step.
4. Previous deals may supply only approved model rules, mappings and regression expectations. Their client, route, payment schedule, amounts, items or other deal-specific values must never be copied into a new deal.
5. ChatGPT asks the manager only for information that is actually absent from all current-deal sources or is genuinely contradictory after source-priority reconciliation.
6. The deterministic calculation/document layer performs the financial calculations and produces the verified Google Sheets/XLSX/PDF package.
7. QA must reconcile source lineage, calculation totals, payment totals, unit economics and client-document rendering before release.

This direct-chat path is the primary production UX. Drive-first is permitted only as an internal technical bridge. The manager is not required to manually move files between ChatGPT, Drive and backend modules.

### DEV-016.42 corrections

`4.1.42` closes two remaining violations of the frozen manager workflow.

First, a partially-created or stale canonical item row no longer causes false questions for item name, quantity, unit, price, currency or TN VED when the current-deal source documents contain a materially more complete and internally consistent item set. For manager-intake only, missing canonical item fields are enriched from the current source documents; when the canonical set is clearly stale and the source set is materially more complete, the source item set is used for intake. Existing non-empty canonical values are not overwritten by the 1:1 enrichment path, and this recovery does not copy data from other deals.

Second, a unique explicit currency rate in approved source rows for the current deal is now selected directly by the calculation rate book as a source-confirmed value. This removes the previous need for a write side effect before a read-only `getDealPackage` call and ensures a single non-conflicting rate never creates a manager confirmation question. Multiple distinct current-deal source rates remain a real conflict and are still blocking.

The manager package contract now also states that already unambiguous source values do not require a separate final confirmation before quote generation.
